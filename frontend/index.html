Triển khai hardening

Chọn máy chủ và các mục cần khắc phục. Sau khi chạy xong, công cụ tự động quét lại và sinh report mới để đối chiếu trước/sau.

Thêm credential SSH

Không có database: chỉ username và đường dẫn tới private key được ghi ra data/credentials.json. Mật khẩu chỉ giữ trong RAM của tiến trình — tắt tool đi là mất, lần chạy sau sẽ hỏi lại. Private key phải KHÔNG đặt passphrase.

Chuẩn bị máy đích trước khi thêm credential

Nên dùng SSH key với một user quản trị riêng, không dùng root: khâu triển khai có mục OS-09/OS-30 ghi PermitRootLogin no, nếu credential là root thì ngay sau lần khắc phục đầu tiên tool sẽ tự khoá mình ra khỏi máy đích.

1. Tạo SSH key trên máy đang chạy tool (bỏ qua nếu đã có) 
ssh-keygen -t ed25519 -C "ansible-hardening" -f ~/.ssh/id_ed25519

Nhấn Enter khi được hỏi passphrase để để trống — tool chạy nền, không có chỗ nhập passphrase. Lệnh tạo ra 2 file: ~/.ssh/id_ed25519 (private key, điền vào form bên trên) và ~/.ssh/id_ed25519.pub (public key, đem lên máy đích).

2. Tạo user quản trị trên máy đích (chạy bằng root, một lần cho mỗi máy) 
# RHEL / CentOS / Rocky / Alma — group quản trị tên 'wheel'
useradd -m -s /bin/bash hardening
passwd hardening
usermod -aG wheel hardening

# Debian / Ubuntu — group quản trị tên 'sudo'
useradd -m -s /bin/bash hardening
passwd hardening
usermod -aG sudo hardening

usermod -aG mới chỉ cho phép user được dùng sudo, sudo vẫn hỏi mật khẩu. Tool chạy nền nên không trả lời được câu hỏi đó: hoặc cho user sudo không cần mật khẩu trên máy đích — 

echo 'hardening ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/hardening
chmod 440 /etc/sudoers.d/hardening
visudo -c

— hoặc điền ô “Mật khẩu sudo” ngay lúc tạo credential ở form bên trên. Bỏ qua cả hai thì lần quét sẽ dừng với lỗi Missing sudo password.

Bước 3 — đưa public key lên máy đích. Hai cách dưới đây cho ra cùng một kết quả, chỉ cần làm một trong hai.

3a. Dùng ssh-copy-id — cách khuyến nghị 
ssh-copy-id -i ~/.ssh/id_ed25519.pub hardening@10.0.0.5

Lệnh này hỏi mật khẩu của user hardening một lần rồi tự ghi public key vào ~/.ssh/authorized_keys trên máy đích, tự tạo thư mục và đặt quyền đúng. Từ lần sau đăng nhập bằng key, không cần mật khẩu nữa. Xong bước này thì bỏ qua 3b, sang thẳng bước 4.

3b. Chép public key thủ công — tuỳ chọn, chỉ khi 3a không dùng được

Cần đến cách này khi máy đích đã tắt đăng nhập bằng mật khẩu (PasswordAuthentication no) nên ssh-copy-id bị từ chối, hoặc máy chạy tool không có sẵn lệnh ssh-copy-id. Trên máy chạy tool, xem nội dung public key: 

cat ~/.ssh/id_ed25519.pub

Vào máy đích bằng console (hoặc bằng user khác đang đăng nhập được), đăng nhập đúng user hardening rồi dán nguyên dòng vừa xem vào: 

mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo 'ssh-ed25519 AAAA... ansible-hardening' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys

Sai quyền là lỗi hay gặp nhất ở cách thủ công: ~/.ssh phải 700, authorized_keys phải 600 và thuộc sở hữu của chính user đó, nếu không sshd sẽ lặng lẽ bỏ qua key mà không báo gì.

4. Kiểm tra trước khi quét 
ssh -i ~/.ssh/id_ed25519 hardening@10.0.0.5 'python3 -V; sudo -n true && echo "sudo khong can mat khau"'

Đây đúng là thứ task “Kiem tra ket noi va python3 tren host dich” kiểm tra. Chạy được là điền form: Username hardening, Kiểu xác thực SSH key, đường dẫn ~/.ssh/id_ed25519.

Đọc kết quả: Permission denied (publickey,password) nghĩa là key chưa lên tới máy đích — quay lại bước 3a/3b. Còn sudo: a password is required nghĩa là SSH đã thông nhưng sudo còn hỏi mật khẩu — quay lại bước 2, vì lúc quét sẽ báo Missing sudo password.

Khi nào mới dùng kiểu “Mật khẩu”?

Chỉ nên dùng để thử nhanh. Ansible cần sshpass trên máy chạy tool mới đẩy được mật khẩu SSH — xem thanh trạng thái góc trên bên phải, nếu báo thiếu sshpass thì kiểu này không chạy được. Cài bằng brew install sshpass (macOS) hoặc apt install sshpass / dnf install sshpass (Linux). Mật khẩu chỉ nằm trong RAM, tắt tool là mất và lần chạy sau tool sẽ hỏi lại.
